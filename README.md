# Presentación: «Code must be written to agreed standards» (XP)
### Materia: Desarrollo Orientado por Objetos (DOPO)

Página estática optimizada para exponer en vivo y ser publicada directamente en **GitHub Pages**.

---

## 🎯 Contenido de la Exposición (4 Ejes Fundamentales)

1. **Portada & Agenda**
2. **Contexto General de la Práctica:** 
   - Ubicación en la fase de *Coding* de Extreme Programming (XP).
   - Por qué surge la necesidad frente al caos de estilos individuales.
3. **¿Qué Propone la Regla?:**
   - El acuerdo colectivo (nombres, formato, estructura, estilo).
   - El ciclo de 4 pasos: Discutir $\rightarrow$ Documentar $\rightarrow$ Automatizar $\rightarrow$ Revisar.
4. **¿Para Qué se Utiliza?:**
   - El sostén de *Pair Programming*, *Collective Ownership*, *Continuous Integration* y *TDD*.
5. **¿Cómo se Usaría en DOPO?:**
   - Vocabulario de negocio (Ubiquitous Language) en nombres de clases y métodos.
   - Principio *Tell, Don't Ask* y encapsulamiento.
   - Límites de responsabilidad única (SRP), cohesión y acoplamiento.

## 🚀 Cómo publicar en GitHub Pages en 3 comandos

```bash
git init
git add .
git commit -m "feat: presentacion agreed standards en DOPO"
git branch -M main
git remote add origin https://github.com/TU_USUARIO/NOMBRE_DEL_REPO.git
git push -u origin main
```
Luego en GitHub: **Settings > Pages > Deploy from a branch (`main` / root)**.
